# R2

`Cloudflare.Workers.R2` (`haskell/cloudflare-workers`) is a typed binding for
[R2](https://developers.cloudflare.com/r2/), Cloudflare's object storage.
Bodies are `Cloudflare.Workers.Fetch` bodies, so an object can be streamed in
from a request or `bodyStream` and out as a response without being held in
memory (see [streaming.md](streaming.md)).

## Configuring a binding

Declare the bucket in `wrangler.toml`; `binding` is the name passed to `r2`:

```toml
[[r2_buckets]]
binding = "FILES"
bucket_name = "<name from `wrangler r2 bucket create`>"
```

## Usage

Serving files, with ranges and conditional requests handled by R2:

```haskell
{-# LANGUAGE OverloadedStrings #-}

import qualified Cloudflare.Workers.Fetch as F
import qualified Cloudflare.Workers.R2    as R2
import qualified Data.ByteString.Char8    as BC
import qualified Data.Text.Encoding       as TE

serve :: R2.R2Bucket -> F.Request -> IO F.Response
serve bucket req = do
  let key = "files/report.pdf"
      -- Only the validators whose failure means 304: see below.
      revalidation = filter ((`elem` ["range", "if-none-match", "if-modified-since"]) . fst) (F.headers req)
  r <- R2.get bucket key (R2.fromRequestHeaders revalidation)
  pure $ case r of
    Nothing -> F.response 404 [] (F.bodyText "not found")
    Just (R2.ConditionFailed o) -> F.response 304 (etag o) F.noBody
    Just (R2.Found o body) ->
      let hs = etag o <> R2.httpMetadataHeaders (R2.httpMetadata o)
       in case R2.range o of
            Just (R2.RangeFrom off (Just len))
              | len < R2.size o ->
                  F.response 206 (("content-range", contentRange off len (R2.size o)) : hs) body
            _ -> F.response 200 hs body
  where
    etag o = [("etag", TE.encodeUtf8 (R2.httpEtag o))]
    contentRange off len total =
      BC.pack ("bytes " <> show off <> "-" <> show (off + len - 1) <> "/" <> show total)
```

Storing an upload as it arrives:

```haskell
upload :: R2.R2Bucket -> F.Request -> IO (Maybe R2.R2Object)
upload bucket req =
  R2.put bucket "uploads/latest" (F.body req)
    R2.defaultPut {R2.putHttpMetadata = R2.defaultHttpMetadata {R2.contentType = Just "application/octet-stream"}}
```

A request body with a `Content-Length` has a known length, which R2 requires
of a stream; see [Streams need a length](#streams-need-a-length).

| Function | Does |
|---|---|
| `r2 env name` | The binding with that name. Throws `EnvMissing` if absent and `R2Exception` if it is not an R2 bucket. |
| `get bucket key opts` | `Nothing` if there is no object; `Found object body`; or `ConditionFailed object` when a condition did not hold (R2 sends no body then). |
| `head bucket key` | The object's metadata, without its body. |
| `put bucket key body opts` | Stores a body and returns the stored object; `Nothing` when a condition did not hold. A JavaScript body is used up. |
| `delete bucket key` | Removes an object; nothing happens if it is absent. |
| `deleteMany bucket keys` | Removes up to 1000 objects in one call. |
| `list bucket opts` | One page of objects in key order. |
| `httpMetadataHeaders meta` | The headers `writeHttpMetadata` would set: `content-type`, `content-language`, `content-disposition`, `content-encoding`, `cache-control` and `expires`. Values are encoded as Latin-1, as header values are, so a `café.txt` filename arrives as `writeHttpMetadata` would send it; a character above U+00FF cannot be sent. |

`R2Object` has `key`, `version`, `size` (of the whole object, an `Int64`: `Int` is 32 bits on wasm), `etag`,
`httpEtag` (quoted, for an `ETag` header), `uploaded`, `httpMetadata`,
`customMetadata` (`Map Text Text`) and `range`, the bytes a `get` returned: the
requested range, or the whole object.

## Ranges and conditions

`GetOptions` takes a typed range and typed conditions:

| Field | Type | |
|---|---|---|
| `getRange` | `Maybe Range` | `RangeFrom offset (Maybe length)` or `RangeSuffix n`, the last `n` bytes. |
| `getOnlyIf` | `Maybe Conditions` | `etagMatches`, `etagDoesNotMatch`, `uploadedBefore`, `uploadedAfter`; start from `noConditions`. |
| `conditionHeaders` | `RequestHeaders` | Headers R2 reads for whichever of the two is not given. |

`fromRequestHeaders hs` fills `conditionHeaders`, so R2 applies a request's
`Range`, `If-Match`, `If-None-Match`, `If-Modified-Since` and
`If-Unmodified-Since` as it parses them. `put` takes the same `Conditions` in
`putOnlyIf`.

A failed condition is `ConditionFailed`, and R2 does not say which condition
failed. In HTTP a failed `If-None-Match` or `If-Modified-Since` means `304`, but
a failed `If-Match` or `If-Unmodified-Since` means `412`. The example above
therefore passes only `Range`, `If-None-Match` and `If-Modified-Since`, so
`ConditionFailed` is always a `304`; to support `If-Match` as well, check it
against the object (`head`, then its `etag`) and answer `412` yourself.

## Streams need a length

R2 accepts a stream only when its length is known: a received request or
response body with a `Content-Length`, or the readable side of a
`FixedLengthStream`. Any other stream is refused with `R2Exception`
("Provided readable stream must have a known length").

For a `bodyStream`, or an upload without a `Content-Length`, set `putSize`: the
stream then goes through a `FixedLengthStream` of that size, still without
being buffered. `putSize` must be the stream's exact length. Bytes
(`bodyBytes`, `bodyText`) need no size.

## Listing

`ListOptions` has `prefix`, `delimiter`, `limit` (at most 1000, the default),
`cursor`, and two flags, `includeHttpMetadata` and `includeCustomMetadata`;
without them, the listed objects' metadata is empty. `list` returns
`ListResult { objects, delimitedPrefixes, nextCursor }`. With a `delimiter`,
keys that contain it after the prefix are grouped into `delimitedPrefixes`,
as directories would be. Pass `nextCursor` back as `cursor`, with the same
options, until it is `Nothing`.

## Limits

- Keys: at most 1024 bytes. Custom and HTTP metadata: at most 8192 bytes.
- A single `put`: at most 5 GiB less 5 MiB (multipart uploads, not covered
  here, go further).
- One write per second to the same key.
- `list` and `deleteMany`: at most 1000 keys.

See [R2 limits](https://developers.cloudflare.com/r2/platform/limits/).

## Errors

`R2Exception` carries the runtime's message for whatever R2 refuses: an
invalid key or range, a stream of unknown length, a size that does not match,
too many writes, too many keys. A missing object is `Nothing`, and a failed
condition is `ConditionFailed` (for `get`) or `Nothing` (for `put`), not an
exception.

Not covered: multipart uploads, checksums, storage classes and SSE-C.

## Testing

Node has no R2, so the bindings are checked only under workerd.
`node scripts/check-wrangler.mjs` runs test-worker's `/r2/flow` against a local
bucket (`[[r2_buckets]]` in `test/wrangler.toml`): put and get, ranges (typed
and from a `Range` header), `If-None-Match` and etag conditions, `head` with
metadata, `httpMetadataHeaders`, a missing object, a conditional put, a stream
with and without `putSize`, `delete`, `list` with a delimiter and paging, the
include flags, `deleteMany`, an invalid key and a non-R2 binding. The same
flow gave the same output against a production bucket.
